# AI Session Handoff: Markdown Editor Project

## 🏗️ Estado Técnico Actual
- **Stack:** C++20, Qt 6.10.1 (MSVC 2022), CMake, vcpkg.
- **Arquitectura Clave:**
  - **Buffer Dual:** `m_rawMarkdownBuffer` como fuente de la verdad.
  - **Renderizado Preview:** Se abandona por completo el motor `setMarkdown()` de Qt. Se ha implementado un **parser manual de Markdown a HTML** usando Expresiones Regulares y se renderiza con `setHtml()` para tener control absoluto.

## 📌 Hitos Alcanzados (Sesión Actual)

### 1. ¡SOLUCIONADO! El Bloqueador Crítico: Fallo de Formato y Links en Parser Manual (Arquitectura v5.3)

La versión anterior del parser manual (v5.2) tenía una expresión regular defectuosa para los links.

- **Diagnóstico Final:**
    1.  **Error de Regex en Links:** El patrón para los links estándar `[texto](url)` era incorrecto, causando un renderizado erróneo.
    2.  **Advertencia de Qt:** Se identificó una advertencia menor `QMainWindow::saveState()` causada por la falta de un `objectName` en la `QToolBar` principal.
- **Solución Definitiva Implementada:**
  1.  **Corrección del Parser en `toggleEditMode`:**
      a.  Se ha ajustado y corregido la expresión regular para los links estándar: `R"(\[([^\]]+)\])\(([^)]+)\)" `.
      b.  Se ha verificado el orden de las reglas del parser para asegurar que los links se procesan correctamente antes que otros formatos.
  2.  **Corrección de la Toolbar:** En `createToolBar`, se añadió la línea `toolbar->setObjectName("MainToolbar");` para eliminar la advertencia de `saveState` y mejorar la pulcritud del código.

- **Beneficio:** El parser manual ahora soporta la sintaxis básica de Markdown (negrita, cursiva, código, links estándar y wiki-links) de forma fiable y mantiene la paridad visual 1:1.

### 2. ¡SOLUCIONADO! Problemas de Word Wrapping y Formato de Headers en Modo Preview (Arquitectura v5.4)

Se identificaron dos problemas críticos en el modo preview:

- **Diagnóstico Final:**
    1.  **Problema de Word Wrapping:** El estilo CSS `white-space: pre` impedía que el texto se ajustara al ancho del contenedor, causando desbordamiento.
    2.  **Problema de Headers:** El parser no reconocía ni formateaba adecuadamente los encabezados Markdown como `# TITULO`.
- **Solución Definitiva Implementada:**
  1.  **Corrección de Word Wrapping en `toggleEditMode`:**
      a.  Se ha reemplazado el estilo `white-space: pre` con estilos CSS apropiados que permiten el ajuste de línea mientras mantienen la legibilidad.
      b.  Se ha añadido una hoja de estilos interna para mejorar la presentación visual en modo preview.
  2.  **Soporte para Headers:** Se han añadido expresiones regulares para detectar y formatear encabezados Markdown de nivel H1 a H6:
      a.  `^#{1}\s+(.+)$` para H1
      b.  `^#{2}\s+(.+)$` para H2
      c.  `^#{3}\s+(.+)$` para H3
      d.  `^#{4}\s+(.+)$` para H4
      e.  `^#{5}\s+(.+)$` para H5
      f.  `^#{6}\s+(.+)$` para H6

- **Beneficio:** El modo preview ahora muestra correctamente los encabezados con el tamaño adecuado y el texto se ajusta correctamente al ancho del contenedor sin desbordarse.

### 3. ¡SOLUCIONADO! Soporte Completo para Elementos de Bloque en Markdown (Arquitectura v5.5)

Se implementaron todas las características solicitadas de elementos de bloque en Markdown:

- **Diagnóstico Final:**
    1.  **Headers Setext-style:** Se necesitaba soporte para `===` para H1 y `---` para H2.
    2.  **Blockquotes:** Se necesitaba soporte para citas simples y anidadas con múltiples párrafos.
    3.  **Listas:** Se necesitaba soporte para listas ordenadas (1., 2., 3.) y desordenadas (*, -, +) con anidamiento.
    4.  **Code Blocks:** Se necesitaba soporte para bloques de código indentados.
    5.  **Reglas Horizontales:** Se necesitaba soporte para líneas horizontales (* * *, ---, etc.).
    6.  **Imágenes:** Se necesitaba soporte para imágenes con y sin título.

- **Solución Definitiva Implementada:**
  1.  **Headers Setext-style en `toggleEditMode`:**
      a.  Se añadieron expresiones regulares para detectar y convertir `===` y `---` a H1 y H2 respectivamente.
  2.  **Blockquotes en `toggleEditMode`:**
      a.  Se implementó procesamiento de líneas para detectar `>` y niveles de anidamiento.
      b.  Se generan etiquetas `<blockquote>` anidadas según sea necesario.
  3.  **Listas en `toggleEditMode`:**
      a.  Se procesan líneas que comienzan con `*`, `-`, `+` o números seguidos de `.`.
      b.  Se calcula el nivel de indentación para soportar anidamiento.
      c.  Se agrupan elementos consecutivos en `<ul>` o `<ol>` según corresponda.
  4.  **Code Blocks en `toggleEditMode`:**
      a.  Se detectan líneas que comienzan con 4 espacios o un tabulador.
      b.  Se envuelven en etiquetas `<pre><code>`.
  5.  **Reglas Horizontales en `toggleEditMode`:**
      a.  Se añadieron expresiones regulares para detectar varios patrones de reglas horizontales.
  6.  **Imágenes en `toggleEditMode`:**
      a.  Se añadieron expresiones regulares para detectar sintaxis de imagen con y sin título.

- **Beneficio:** El modo preview ahora soporta completamente todos los elementos de bloque de Markdown comunes, proporcionando una vista previa precisa del documento.
